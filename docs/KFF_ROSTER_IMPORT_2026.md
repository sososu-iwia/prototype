## Источники и границы достоверности

[Страница команды KFF](https://kffleague.kz/ru/team/81) содержит 30 игроков и трёх тренеров. Проверка 1 ноября 2026 через публичный web reader дала метаданные 28 индивидуальных профилей. Профили Улар Жаксыбаев (#8) и Султанбек Астанов (#22, ID 1511) недоступны для полного чтения. Прямой HTTP-запрос KFF вернул 403; обход блокировки и недокументированные API не применялись. `--refresh` при таком ответе прекращает импорт. Проверенный снимок, способ получения и дата сохранены в `packages/content/kff-2026-source.json`; он не выдаётся за постоянно обновляемый API или доказательство текущего контракта.

CSV из пакета сверен с актуальным списком всех 30 строк: имя, номер, позиция и гражданство совпали. Индивидуальные профили дают дополнительные расхождения. Статистика, даты контрактов, рост, биографии, даты рождения и фотографии из внешних сайтов не импортировались.

Таблица `RosterImportRecord` хранит source URL, profile URL/ID, capturedAt, исходные значения, предложенный local ID/team/position, конфликты, алиасы, решение, комментарий, автора и версию. Админка ADMIN/SUPER_ADMIN позволяет Approve/Reject/Edit/Defer. EDIT возвращает запись в PENDING; повторный импорт не отменяет решения. EDITOR и анонимный пользователь не имеют доступа. Все изменения требуют CSRF/Origin и If-Match, проходят audit и транзакционную блокировку. Назначение профиля «Ордабасы М» в first-team отклоняется; существующий PlayerSeason другой команды защищён от перезаписи.

## Воспроизводимый запуск

Команды получают `DATABASE_URL` из закрытой QA-конфигурации, а не из исходной пользовательской `.env`:

```sh
node scripts/import-kff-ordabasy-2026.mjs --dry-run --report /private/tmp/kff-diff.json
node scripts/import-kff-ordabasy-2026.mjs --apply-to-test --publish-confirmed-to-test --report /private/tmp/kff-applied.json
node scripts/import-kff-ordabasy-2026.mjs --apply-to-test --publish-confirmed-to-test --report /private/tmp/kff-repeat.json
```

Повторный apply: **0 игроков, 0 записей сверки, 0 тренеров, 0 черновиков, 0 периодов**. Требуются PostgreSQL 17+ и отдельный маркер `test` в имени базы. Старый `codex` в имени не даёт права записи. `--apply` в реальную БД намеренно запрещён; перенос данных требует отдельного согласования владельца и backup/restore процедуры. Обычный `db:seed` сохраняет прежние безопасные публикационные defaults и не выполняет KFF-публикацию автоматически.

Просмотр `/ru/teams/first-team?season=2026` показывает утверждённые сезонные записи. `/ru/teams/first-team` сохраняет строгий фильтр действующих, проверенных контрактных периодов. Профиль нового игрока показывает источник заявки и отсутствие подтверждения контракта. Административные комментарии и pending records публично не сериализуются.
