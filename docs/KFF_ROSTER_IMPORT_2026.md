## Воспроизводимый запуск

Команды получают `DATABASE_URL` из закрытой QA-конфигурации, а не из исходной пользовательской `.env`:

```sh
node scripts/import-kff-ordabasy-2026.mjs --dry-run --report /private/tmp/kff-diff.json
node scripts/import-kff-ordabasy-2026.mjs --apply-to-test --publish-confirmed-to-test --report /private/tmp/kff-applied.json
node scripts/import-kff-ordabasy-2026.mjs --apply-to-test --publish-confirmed-to-test --report /private/tmp/kff-repeat.json
```

Повторный apply: **0 игроков, 0 записей сверки, 0 тренеров, 0 черновиков, 0 периодов**. Требуются PostgreSQL 17+ и отдельный маркер `test` в имени базы. Старый `codex` в имени не даёт права записи. `--apply` в реальную БД намеренно запрещён; перенос данных требует отдельного согласования владельца и backup/restore процедуры. Обычный `db:seed` сохраняет прежние безопасные публикационные defaults и не выполняет KFF-публикацию автоматически.

Просмотр `/ru/teams/first-team?season=2026` показывает утверждённые сезонные записи. `/ru/teams/first-team` сохраняет строгий фильтр действующих, проверенных контрактных периодов. Профиль нового игрока показывает источник заявки и отсутствие подтверждения контракта. Административные комментарии и pending records публично не сериализуются.
