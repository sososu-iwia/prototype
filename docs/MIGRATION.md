# Миграция и проверка фактов

1. `npm run content:import` читает исходные `team.html`, `matches.html`, `index.html` и словари `js/script.js`. Извлекаются 20 карточек, 36 матчей, 17 команд, 3 новостных заготовки и 6 элементов галереи. Скрипт ограниченно вычисляет только литералы из доверенных локальных исходников в VM с timeout; его нельзя применять к произвольным загруженным файлам.
2. `npm run media:build` строит варианты и MP4/poster в `apps/web/public/media`, сохраняя originals. FFmpeg извлекает PNG-frame; Sharp кодирует poster, поэтому WebP encoder в FFmpeg не требуется.
3. `node scripts/build-snapshot.mjs` создаёт аварийную публичную копию и копирует три Noto subsets + OFL. Наборы проверены fontkit на казахском, русском и английском алфавите.
4. `npm run db:migrate` применяет versioned SQL. `npm run db:seed` импортирует при первом запуске; наличие `ClubSettings/main` означает завершённую инициализацию. Всё выполняется в транзакции. Повтор не перезаписывает редактуру, удалённые записи не восстанавливаются автоматически.
5. `npm run admin:create` создаёт нового SUPER_ADMIN из окружения. Пароль Argon2id; существующий email отклоняется.

Матчи legacy помечены DRAFT: их результаты и даты не подтверждены. Неизвестное время из старого массива сохраняется только как часть исходной черновой записи; редактор обязан уточнить kickoff перед публикацией. Все сырые поля сохранены в `legacy-import.json.original` и оригинальном HTML. Никогда не выдавайте условные 12:00 из импорта за установленное время матча.

Игроки сохранены публично как архив прежнего состава, с отдельным уведомлением и sourceDate. Текущий состав и номера нуждаются в сверке. English names получены из исходных имён файлов и также не считаются подтверждённым официальным написанием. Биографии, рост, дата рождения, статистика не восстановлены догадками.

Старые новости не подтверждают реальные события; 3 записи доступны редактору как DRAFT. Публичная служебная заметка `website-archive` описывает только действительно сохранённые данные репозитория. Она не является вымышленной клубной новостью. Дата сохранена в UTC с учётом начала 19 октября 2026 в Asia/Almaty.

## Первичные источники для редакторской сверки

Просмотрены официальный сайт клуба <https://fcordabasy.kz/ru/about-us> и карточка ПФЛ <https://pfl.kz/rus/clubs/25/>. Официальная страница содержит в том числе устаревший текст о сезоне 2018; её наличие само по себе не подтверждает состав/таблицу 2026. ПФЛ приводит предшествующие названия клуба. Это требует отдельного отделения истории городского футбола, спортивной преемственности и юридического лица; произвольная дата «основан в 2000» не была объявлена доказанной. Никакой scraping-интеграции не внедрено.

Редактору необходимо: получить подтверждённый roster/номера, источники текущих матчей, историю/достижения с датами, персоналии руководства/штаба и разрешения на имеющиеся медиа. Для каждой записи можно задать source, sourceDate и VERIFIED. Не публикуйте как VERIFIED без проверки источника.

Оригинальные четыре публичные страницы/новости сохраняют URL через Next redirects. `legacy/netlify` — архив прежних provider-функций, активный Netlify bridge не содержит ключа/жёстко зашитых сезонов. Root legacy HTML не входит в Docker/Next bundle. Не публикуйте корень как static hosting после миграции.


Дополнительные миграции `20261019010000_professional_cms` и `20261019020000_roster_provenance` добавляют сущности/поля, backfill периодов из существующих PlayerSeason и запрет уничтожения истории. Исходные IDs и первая миграция не переписываются. Imported startsAt — дата известного архивного снимка, `datesVerified=false`, а не утверждение о точном переходе. На пустой БД seed создаёт те же периоды; повторный seed не меняет редактуру. Новые автоматически генерируемые PK — UUID; logical legacy IDs (2026/league/ordabasy/main) сохранены ради совместимости ссылок. Перед production-применением нужен backup и просмотр SQL; migrate deploy не выполняет reset/down/drop.
