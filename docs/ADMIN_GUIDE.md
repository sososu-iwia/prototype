# Управление FC Ordabasy

Панель находится по `/admin` (с перенаправлением на выбранный язык), а также `/kk/admin`, `/ru/admin`, `/en/admin`. Все изменения отправляются в NestJS и PostgreSQL. Публичные страницы получают данные через API без постоянного кеша; после сохранения откройте или обновите публичную страницу.

## Первый пользователь и права

Создайте первого пользователя командой `BOOTSTRAP_ROLE=SUPER_ADMIN npm run admin:create`, передав `ADMIN_EMAIL` и `ADMIN_PASSWORD` через окружение. Пароль 16–128 символов. Не сохраняйте его в репозитории. Команда не перезаписывает существующий аккаунт. Публичной регистрации нет.

| Роль | Полномочия |
| --- | --- |
| SUPER_ADMIN | Весь контент, настройки, журнал, создание/изменение всех ролей |
| ADMIN | Футбол, контент, настройки, журнал; создание и изменение только EDITOR |
| EDITOR | Свои новости, галерея, загрузка и описание изображений; чтение справочников |

Отключение пользователя, смена роли или пароля отзывает все его сессии. Нельзя отключить себя или понизить собственную роль. Последний активный SUPER_ADMIN защищён. Пароли и хеши не возвращаются в списке пользователей.

## Игрок, состав и уход

1. В «Игроки» создайте профиль: slug, имя на KK, позиция, источник. RU/EN необязательны: отсутствующий перевод использует KK. Добавьте фото через загрузку или медиатеку. Опубликуйте профиль, когда сведения проверены.
2. Кнопка «Карьерная история» открывает периоды конкретного игрока. Создайте период: команда, сезон, номер, начало. У команды клуба должна быть включена отметка «Состав клуба»; соперникам её не ставят.
3. Для ухода откройте **активный период**, укажите окончание, причину и новый клуб. При необходимости отдельно измените статус профиля на DEPARTED/LOANED_OUT/RETIRED. Статус здоровья и принадлежность составу — независимые данные.
4. Игрок исчезнет из текущего состава после окончания периода. Опубликованный `/players/slug` и статистика сохраняются. Публичный `/players` показывает архив и фильтр сезона.
5. При возвращении создайте **новый** период с новым началом и номером. Существующий сезонный итог останется тем же: перенос не создаёт второй экземпляр статистики.
6. Номер текущей карточки берётся из периода состава. Раздел «Игроки по сезонам» хранит стабильную связь для сезонной статистики, а не заменяет периоды состава.

Периоды `[начало, окончание)` одного игрока в одной команде не пересекаются, включая разные сезоны. Соседние периоды разрешены. Изменение идентичности исторического периода и удаление сезонных итогов запрещены. Исправляйте запись или завершайте период. Даты импортированного снимка помечены как неподтверждённые: они не выдаются за известные даты переходов.

Архив игрока хранится в отдельной дате, а его публикационный статус имеет только DRAFT/PUBLISHED. «Архивировать» у игрока завершает активные периоды, сохраняет профиль и историю. Для восстановления откройте профиль, очистите «Дата архивации» и сохраните; затем создайте новый период состава. Архивный статус можно найти фильтром. Для новости/матча/галереи архивирование меняет публикационный статус на ARCHIVED; восстановление выполняется через DRAFT/PUBLISHED.

## Сезоны, матчи и статистика

Новый сезон получает UUID, название, год, границы и статус. Отметка «Текущий» может быть только у одного сезона. Переключение не удаляет предыдущие составы и показатели.

Матч связывается с сезоном, турниром и разными домашней/гостевой командами. Время формы — **Asia/Almaty, UTC+5**, API хранит UTC. Даты рождения и границы сезона вводятся как календарные даты без смещения. Статусы: SCHEDULED, LIVE, FINISHED, POSTPONED, CANCELLED. Завершённому матчу необходим неотрицательный счёт.

Кнопки у матча открывают его события и показатели игроков. Событию нужны уникальный ключ, игрок, команда, минута, тип и источник. Игрок должен состоять в одной из команд на момент матча. Одинаковый ключ не принимается повторно. Для ошибки включите «Событие отменено», сохраняя историю. Сумма голов/передач команды не может превышать её счёт; для уменьшения счёта сначала исправьте ошибочные события. Матч с историей нельзя незаметно переназначить другой паре команд, сезону или времени.

Два взаимоисключающих режима сезонной статистики:

- **CONFIRMED** — явно подтверждённые итоги из указанного источника. Неизвестные карточки и сухие матчи оставляйте пустыми.
- **MATCHES** — только подтверждённые персональные строки опубликованных, проверенных, завершённых матчей. Выходы/минуты/сухие матчи берутся из строк, голы/передачи/карточки — из неотменённых событий. Пара матч+игрок уникальна. Без подходящих строк рейтинг пустой.

Сезонные итоги и матчевые события не складываются. Отмена/архивирование матча и исправление события немедленно меняют расчёт. «Сухой матч» допускается только для вратаря при нулевых пропущенных; при изменении результата подтверждённый показатель корректируется. Рейтинг «эффективность» использует `(голы + передачи) × 90 / минуты`, без деления на ноль. Это не награда «лучший игрок».

## Новости и изображения

Новость хранит отдельные заголовок/анонс/текст для KK/RU/EN, категорию, обложку, галерею ссылок, источник, автора-создателя и дату публикации. Автор назначается сервером. Начните с DRAFT, используйте предпросмотр и опубликуйте с прошедшей/текущей датой. Для снятия публикации верните DRAFT. Текст — безопасный обычный текст: HTML/JavaScript не исполняются, переводы автоматически не генерируются.

Медиатека принимает JPEG/PNG/WebP до 10 MiB. Формат проверяется по содержимому; создаются WebP, AVIF и миниатюра, EXIF удаляется. Можно менять локализованное описание и выбирать ранее загруженную обложку/фотографию. Неиспользуемый файл может удалить ADMIN/SUPER_ADMIN; ссылки в опубликованных, черновых и архивных записях защищают файл от удаления. Production сохраняет файлы в независимом S3 bucket, PostgreSQL — ссылки и метаданные. При переезде используйте `media:migrate-storage` и инструкцию развёртывания.

## Сохранение и конфликты

Во время сохранения блокируются форма, смена раздела и выход. Создание использует сохранённый в PostgreSQL ключ идемпотентности. Если другой администратор сохранил запись раньше, сервер возвращает 409, а ваша форма остаётся открытой. Нажмите «Обновить версию, сохранив форму»: ваши изменённые поля сохраняются, нетронутые получают актуальные значения. Если оба редактора изменили одно поле, панель перечисляет такие поля и просит подтвердить сохранение ваших значений. Отмена оставляет форму и старую версию без изменений. После объединения проверьте форму и сохраните её; автоматического перезаписывания чужой версии нет.

Несохранённая форма защищена при смене раздела, переходе по ссылкам и закрытии/перезагрузке вкладки. Опасные действия требуют модального подтверждения. Журнал показывает автора действия, время, раздел/ID, безопасные изменения и результат; длинный текст сокращается, секреты не записываются.
