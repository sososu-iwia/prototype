# Архив и размер репозитория

24 октября 2026: локально `images/` занимает 331 MiB, `docs/` до новых проверок — 74 MiB, `.git/` — 292 MiB, оптимизированный `apps/web/public/` — 16 MiB. Разница с ZIP обусловлена единицами измерения и составом файлов. Исходные HTML/CSS/JS, изображения и видео не удалялись, история Git не переписывалась.

Безопасный следующий этап после согласования владельцем:

1. Создать versioned архив исходных `images/`, `css/`, `js/`, HTML и существующих baseline/verification в отдельном защищённом хранилище. Сгенерировать SHA-256 manifest и проверить распаковку/совпадение каждого файла. Хранить две копии с разными отказами; внешнее хранилище здесь не настроено.
2. Зафиксировать в Git небольшой manifest: относительный путь, размер, SHA-256, версия архива и постоянное местоположение. Оптимизированные используемые файлы `apps/web/public` остаются частью исходников/сборки. Сборка не должна зависеть от загрузки архива.
3. Переносить тяжёлые оригиналы из checkout только отдельным согласованным изменением после проверки копий, ссылок и лицензий. Старый `.git` от такого переноса не уменьшится; переписывание истории требует отдельного решения команды, резервной копии и координации клонов.
4. Новые Lighthouse JSON/скриншоты/логи хранить как CI artifacts с политикой retention и отдельным offsite архивом важных релизов. Markdown-документация теперь доступна Git; тяжёлые `docs/verification` и `docs/baseline` остаются исключёнными. Прежние исторические доказательства на диске сохранены.

Никакой перенос, удаление оригиналов или выгрузка в сторонний аккаунт в этой работе не выполнялись.
